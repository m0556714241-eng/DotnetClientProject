# SeatWise – Client (React)

הקליינט של SeatWise: גילוי אירועים, **מפת אולם אינטראקטיבית** עם בחירת מושב מדויק, והזמנה מול שרת ה-.NET (`SeatWise.API`).

- **שרת:** https://github.com/m0556714241-eng/SeatWise
- **אתר חי:** _(יעודכן אחרי ההעלאה ל-Render)_

## טכנולוגיות

| נושא | בחירה |
|---|---|
| בנייה | Vite + React 18 + TypeScript (strict) |
| ניווט | React Router 6 |
| נתוני שרת | TanStack Query 5 (cache, טעינה, רענון אחרי פעולות) |
| טפסים | React Hook Form 7 (ולידציה זהה לכללי ה-DTO בשרת) |
| HTTP | Axios – מופע אחד מרכזי (`src/api/client.ts`) |
| עיצוב | CSS Modules + משתני CSS מרכזיים (`src/styles/tokens.css`), RTL מלא, גופן Rubik, אייקונים lucide-react |

אין ספריית UI חיצונית: כל הרכיבים נכתבו כאן.

## הרצה מקומית

1. להריץ את השרת (`SeatWise.API`, פרופיל https → `https://localhost:7180`). קונטיינר ה-PostgreSQL חייב לרוץ.
2. בתיקיית הקליינט:

```bash
npm install
copy .env.example .env      # ב-Windows (או cp ב-Mac/Linux)
npm run dev
```

3. לפתוח את http://localhost:5173

> הפורט 5173 קבוע (`strictPort`), כי ה-CORS בשרת (`Cors:AllowedOrigins`) מאשר בדיוק את הכתובת הזו.
> אם הדפדפן חוסם את `https://localhost:7180`, צריך להריץ פעם אחת `dotnet dev-certs https --trust`.

## מפת המושבים – איך זה עובד

- **הנתונים אמיתיים:** `GET /api/events/{id}` מחזיר את `RowsCount`, `SeatsPerRow`, `Sections` (שם, מחיר, טווח שורות) ו-`Seats` (מזהה, שורה, מושב, `Available`/`Booked`). כל מושב במפה הוא מושב מהשרת.
- **הצורה:** האולם בשרת הוא שורות × מושבים, ו-`hallLayout.ts` מצייר אותו כמניפה: שורה 1 קרובה לבמה, ומושב 1 בצד ימין. המעברים בין גושי המושבים, והמעבר בין אזורי המחיר, הם רווחים חזותיים בלבד.
- **צבעים:** כל אזור מקבל צבע לפי דירוג המחיר האמיתי שלו (היקר ביותר בזהב). מושב **תפוס** מוצג אפור עם ✕, ומושב **שנבחר** מוצג לבן עם מסגרת ו-✓. כך המצב לא מועבר רק בצבע.
- **אינטראקציה:** לחיצה בוחרת או מבטלת, גרירה מזיזה את המפה, צביטה או Ctrl+גלגלת מגדילות, ויש כפתורי +/−/"כל האולם". במסך קטן המפה נפתחת מוגדלת על השורות הקדמיות. במקלדת: Tab נכנס למפה, החיצים עוברים בין מושבים ו-Enter/רווח בוחרים. לכל מושב יש `aria-label` מלא.
- **סנכרון:** המפה והסיכום קוראים מאותו hook (`useSeatSelection`), שמחזיק רק מזהי מושבים. הפרטים, המחירים והסכום **מחושבים** מנתוני השרת, ולא נשמרים בנפרד.
- **מגבלה:** עד 10 מושבים, כמו `CreateBookingDto` (`MaxLength(10)`), שגם השרת אוכף.

## תהליך ההזמנה

1. בוחרים מושבים, והסיכום מתעדכן מיד.
2. **"המשך להזמנה"**: אם המשתמשת לא מחוברת, היא עוברת להתחברות. המושבים נשמרים ב-`sessionStorage` (מזהים בלבד), ואחרי ההתחברות היא חוזרת למפה.
3. לפני האישור הקליינט **טוען שוב את הזמינות מהשרת**. מושב שנתפס בינתיים יורד מהבחירה, ומוצגת הודעה עליו.
4. בחלון הסיכום מופיעים האזור, השורה והמושב, המחיר של כל כרטיס וסה"כ. אחר כך נשלח `POST /api/bookings` עם `{ eventId, seatIds }`. השרת יוצר הזמנה בסטטוס **`PendingPayment`** ושומר את המושבים ל-10 דקות. הכפתור ננעל בזמן השליחה.
5. **תשלום** (`/bookings/:id/pay`): טיימר עד `paymentDueAt` וטופס כרטיס. פרטי הכרטיס עוברים רק ל"ספק התשלום" (`utils/mockPaymentProvider.ts`, מדומה), שמחזיר אסימון חד-פעמי. לשרת נשלח רק `POST /api/bookings/{id}/pay` עם `{ paymentToken }`.
   - כרטיסי בדיקה: `4242 4242 4242 4242` מאושר, ו-`4000 0000 0000 0002` נדחה. כל תוקף עתידי ו-CVV כלשהו.
   - נדחה (400): נשארים בעמוד ואפשר לנסות כרטיס אחר. הזמן עבר (409): המושבים שוחררו, וחוזרים למפה.
   - "ביטול ושחרור המושבים" שולח `DELETE` ומשחרר מיד.
6. **הצלחה:** עמוד האישור (שלב 3) עם הנתונים שהשרת החזיר.
7. **409 ביצירה:** מוצגת ההודעה "אחד המושבים שבחרת נתפס בינתיים...", הזמינות נטענת מחדש מהשרת, והמושבים שנתפסו הופכים אפורים ויורדים מהבחירה. **שאר המושבים נשארים בחירים**, והסכום מתעדכן.

## שגיאות

כל השגיאות עוברות דרך `api/errors.ts`, שממיר את ה-`ErrorResponse` האחיד של השרת (`{ status, message, errors? }`) להודעה בעברית:
- הודעות עסקיות מוכרות מתורגמות במדויק (למשל `Wrong email or password` → "אימייל או סיסמה שגויים"). הודעה לא מוכרת מקבלת הודעה כללית לפי הסטטוס, וטקסט באנגלית מהשרת לא מוצג.
- **400** עם `errors`: השגיאה מוצגת ליד השדה המתאים בטופס.
- **401:** ה-interceptor מנקה את ההתחברות ומעביר ל-`/login` **פעם אחת**, גם כשכמה בקשות נכשלות יחד, ואחרי ההתחברות חוזרים לאותו עמוד. 401 מ-`/auth/login` הוא "סיסמה שגויה" ולא פג תוקף.
- **403:** הודעת "אין הרשאה", בלי ניתוק.
- **409:** טיפול מיוחד בהזמנה (למעלה), ובשאר המקומות הודעה ורענון.
- רשת או 500: הודעה ידידותית וכפתור "ניסיון נוסף".

## הרשאות (בממשק)

- אורחת: צופה באירועים ובמפה ובוחרת מושבים. כדי להזמין צריך להתחבר.
- **Customer:** הזמנה, "ההזמנות שלי" וביטול לפני תחילת האירוע.
- **Admin:** ניהול אירועים (יצירה, עריכה, מחיקה, העלאת תמונה) וכל ההזמנות. כפתור ההזמנה מוסתר, כי השרת מחזיר 403 למנהלת שמזמינה.

הסתרה בממשק היא רק נוחות. האבטחה האמיתית היא `[Authorize]` בשרת.

## אחסון הטוקן – שיקולים

ה-JWT נשמר ב-`localStorage` (בקובץ אחד: `auth/session.ts`). זה פשוט ושורד רענון, אבל כל סקריפט בעמוד יכול לקרוא אותו. לכן:
- אין שימוש ב-`dangerouslySetInnerHTML` ואין HTML לא מאומת.
- הטוקן לא נכתב ללוג.
- הסשן נמחק כשהתוקף פג (טיימר לפי `expiresAt`) או כשהשרת מחזיר 401.
- נשמרים רק פרטים בסיסיים (שם, אימייל, תפקיד), ולא סיסמה.

חלופה מאובטחת יותר היא cookie מסוג HttpOnly, אבל היא דורשת שינוי בשרת.

## העלאה ל-Render (Static Site)

- **Build Command:** `npm install && npm run build`
- **Publish Directory:** `dist`
- **Environment:** `VITE_API_URL=https://<שם-השרת>.onrender.com`. המשתנה נקרא **בזמן ה-build**, אז אחרי שינוי צריך לבנות מחדש.
- **Rewrite:** `/*` → `/index.html` (Rewrite), כדי שרענון בעמוד פנימי כמו `/events/3` לא יחזיר 404.
- **בשרת:** להוסיף את כתובת הקליינט ל-CORS: `Cors__AllowedOrigins__0=https://<שם-הקליינט>.onrender.com`.

## מגבלות ידועות (מה שהשרת לא מספק)

- **אין קטגוריה לאירוע** (מוזיקה/תיאטרון), ולכן אין סינון לפי קטגוריה. הסינון הוא לפי שם וטווח תאריכים, והמיון לפי תאריך או שם, כמו `EventQueryDto`.
- **אין סינון לפי מקום או מחיר** ב-API, ולכן הם לא קיימים בקליינט. הקליינט לא מסנן מקומית על עמוד חלקי.
- **צורת האולם:** בשרת האולם הוא שורות × מושבים. אין נתונים על אזורי צד, כניסות או מושבים נגישים, ולכן הם לא מוצגים כנתון.
- **פירוט ה-409:** השרת מחזיר טקסט ("row X seat Y"). הקליינט לא מפענח אותו, אלא טוען מחדש את מפת המושבים ומשווה, וזה מקור אמין יותר.
- **מושב שנבחר אינו שמור** עד שהשרת מאשר את ההזמנה (אין נעילה זמנית). זה מוצג למשתמשת בעמוד.
